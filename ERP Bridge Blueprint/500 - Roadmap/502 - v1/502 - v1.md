# 502 - v1 (Versión 1.0)

> *Transformación del MVP en producto comercial, multi-conector, motor de automatizaciones y plataforma escalable.*

---

## 1. Propósito

Definir las funcionalidades necesarias para transformar el MVP de ERP Bridge en una primera versión estable, utilizable y comercializable.

La v1 deberá convertir el prototipo funcional en un producto que pueda ser utilizado por empresas reales sin depender constantemente de intervención técnica por parte de Cristian.

---

## 2. Objetivo de v1

ERP Bridge v1 permite a una empresa conectar sus sistemas existentes y automatizar el intercambio de información entre ellos sin cambiar su ERP y sin necesitar desarrollar integraciones desde cero.

---

## 6. Priorización Validada de Conectores para v1

Tras el estudio exhaustivo de mercado, desatención de competidores y reutilización técnica de código, la secuencia de conectores para v1 se fija en:

```text
CONECTORES DE ENTRADA (ERPs Locales)           CONECTORES DE SALIDA (Canales & Marketplaces)
┌────────────────────────────────────────┐     ┌────────────────────────────────────────┐
│ 1. SimplyGest (Access .mdb - Quick Win)│     │ 1. PrestaShop (Web Service JSON/XML)   │
│ 2. ClassicGes 6 & Visionwin (DBF / xBase)    │ 2. Mirakl Universal (Leroy, PcComp...) │
│ 3. Sage 50 / Eurowin (MS SQL Server)   │     │ 3. Portal Privado B2B (Mayoristas)     │
│                                        │     │ 4. Shopify (GraphQL Admin API)         │
└────────────────────────────────────────┘     └────────────────────────────────────────┘
```

### Criterios de Selección Aplicados:
1. **SimplyGest como Entrada Inmediata:** Reutiliza el 90% del motor `AccessDriver` existente, tiene 35.000 clientes en España y su conector oficial (WebLinker) falla continuamente al exigir el puerto 3306.
2. **PrestaShop como Salida E-commerce Inmediata:** Ataca el 40% del comercio industrial en España (ferretería, recambios, textil) con soporte nativo de Recargo de Equivalencia y catálogos de >10.000 referencias.
3. **Conector Universal Mirakl como Salida Multi-Marketplace:** Abre simultáneamente Leroy Merlin, PcComponentes, Carrefour y MediaMarkt con una sola base de código REST unificada.
4. **Portal B2B Privado:** Monetiza al 70% de clientes de Factusol que son distribuidores mayoristas y necesitan un portal cerrado para pedidos recurrentes de clientes profesionales con tarifas personalizadas.

### Detalle de las 5 Fases Quirúrgicas de Ejecución:

- **Fase 0: Blindaje de WooCommerce (Delta Sync + R.E.) + Lanzamiento a coste 0 € en bridge.cristianjm.com:**
  - Descarte local por triple hash (data, price, stock) para reducir en un 95% las peticiones HTTP a WordPress.
  - Micro-lotes de 25 productos con throttling defensivo (pausa tras peticiones lentas >1.500 ms).
  - Recargo de Equivalencia (R.E.) mapeado bidireccionalmente a la columna `REQPCL` de Factusol (`F_PCL`).
  - Blindaje y omisión de imágenes en actualizaciones para evitar duplicaciones y colapso de CPU en hostings compartidos.
  - Transacciones atómicas seguras en Access OLEDB (`BeginTrans`/`CommitTrans`/`RollbackTrans`) en `AccessDriver`.
  - Landing page oficial en `bridge.cristianjm.com` a coste 0 € con Stripe Checkout y Plan Base Todo Incluido (249 €/año / 199 € Early Bird o 29 €/mes).

- **Fase 1: Conector SimplyGest (Quick Win de entrada sobre AccessDriver):**
  - Paquete `@erp-bridge/connector-simplygest` sobre `Datos.mdb` reutilizando el motor `AccessDriver`.
  - Mapeo completo de `ARTICULOS`, `CLIENTES` y transacciones en `PEDIDOS_VENTA` y `LINEAS_PEDIDOS`.
  - Superación de los bloqueos de WebLinker sin requerir apertura del puerto 3306.
  - Validación comercial con los primeros clientes de pago.

- **Fase 2: Conector PrestaShop (Salida industrial y catálogos masivos):**
  - Paquete `@erp-bridge/connector-prestashop` conectando con el Web Service oficial de PrestaShop 1.7 / 8.
  - Motor dual JSON (lecturas rápidas) y XML (escrituras seguras).
  - Actualización directa de la tabla `ps_stock_available` y combinaciones complejas talla/color.

- **Fase 3: Conector Universal Mirakl (Leroy Merlin, PcComponentes, Carrefour):**
  - Paquete `@erp-bridge/connector-mirakl` con cliente REST unificado para marketplaces Mirakl en España.
  - Sincronización continua de ofertas (`POST /api/offers`), inventario en tiempo real y descarga de pedidos con tracking.

- **Fase 4: Portal B2B Mayorista + Conectores DBF (ClassicGes 6 / Visionwin) + Shopify GraphQL:**
  - Portal web privado B2B para pedidos y descarga de documentos de clientes mayoristas de Factusol.
  - Driver nativo `DbfDriver` para archivos `.dbf` de ClassicGes 6 y Visionwin.
  - Conector Shopify mediante GraphQL Admin API para tiendas e-commerce de alto volumen.

El producto deberá intentar resolver problemas comunes mediante:
- Diagnostics
- Logs
- Error Messages
- Documentation

antes de requerir soporte humano.

---

## 79. v1 Success Criteria

ERP Bridge v1 será considerada exitosa cuando:
- [x] Empresas reales puedan utilizarla
- [x] Nuevos usuarios puedan configurarla
- [x] Existan múltiples Connectors
- [x] Las automatizaciones sean estables
- [x] El Agent sea fiable
- [x] Los errores sean visibles
- [x] El sistema sea mantenible
- [x] Pueda cobrarse por el servicio

---

## 80. Commercial Readiness

La v1 deberá permitir que ERP Bridge pueda ofrecerse comercialmente como:

```text
Software + Infrastructure + Connectors + Automation + Support
```

---

## 81. Product Positioning

ERP Bridge no se venderá simplemente como *"Un conector de Factusol"*.

La propuesta será:

> **Una capa de conectividad que permite a las empresas conectar sus sistemas existentes con aplicaciones modernas sin cambiar su software actual.**

---

## 82. Competitive Positioning

ERP Bridge competirá conceptualmente en el espacio de:
- Zapier
- n8n
- Make
- Integradores tradicionales
- Desarrollos a medida

pero con una especialización diferente:

> **Conectar sistemas empresariales que normalmente no están preparados para conectarse fácilmente.**

---

## 83. Core Differentiator

La diferenciación principal será:

```text
Existing Systems ──> ERP Bridge ──> Modern Internet
```

sin obligar al cliente a:
- Cambiar ERP
- Subir base de datos
- Contratar desarrolladores
- Construir integraciones manualmente

---

## 84. Three-Minute Philosophy

La filosofía de producto será:

> **Si una integración puede configurarse en tres minutos, no debería requerir tres días de desarrollo.**

---

## 85. v1 Anti-Scope

No se incluirá automáticamente:
- Full CRM
- Full ERP
- Full Ecommerce Platform
- Accounting Software
- Project Management
- HR Platform
- Complex AI Agent

> **ERP Bridge conecta sistemas; no intenta reemplazarlos.**

---

## 86. v1 Architecture Principle

La arquitectura seguirá siendo:

```text
Modular Monolith + Agent + Connectors + API + Dashboard + PostgreSQL
```

*(No se introducirán microservicios únicamente por razones de moda tecnológica).*
