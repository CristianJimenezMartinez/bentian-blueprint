# 305 - SDK

> *Software Development Kit para el desarrollo de conectores y extensiones.*

---

## 1. Propósito

El **SDK de ERP Bridge** proporciona las herramientas, interfaces, contratos de tipos y utilidades necesarias para desarrollar conectores y extensiones compatibles con la plataforma.

> **Objetivo fundamental:** Un desarrollador debe poder crear un conector robusto sin necesidad de conocer los detalles internos de implementación del Core.

---

## 2. Problema que Resuelve

### ❌ Sin SDK (Barrera Alta y Acoplamiento):
```text
Desarrollador ──> Debe conocer todo el Core ──> Complejidad excesiva ──> Ecosistema estancado
```

### ✅ Con SDK (Abstracción y Escalabilidad):
```text
Desarrollador ──> ERP Bridge SDK ──> Crear Connector ──> Conectar a ERP Bridge
```

---

## 3. Principio Fundamental

> **El SDK debe exponer únicamente las capacidades necesarias para construir una extensión, ocultando por completo la complejidad interna del Core.**

---

## 4. Qué Permitirá Construir

- Conectores para ERPs, Ecommerce, CRMs y Pasarelas de Pago.
- Adaptadores de protocolo y bases de datos locales.
- Transformaciones de datos reutilizables.
- Triggers y generadores de eventos.
- Acciones de mutación y sincronización.
- Plugins y extensiones a medida.

---

## 5. Estructura Conceptual del SDK

```text
ERP Bridge SDK
│
├── Connector API (Lifecycle & Interfaces)
├── Authentication Handlers (OAuth, API Key, Basic, Agent)
├── Data Models (Canonical Types: Product, Order, Customer...)
├── Events Emitter (Disparadores de eventos)
├── Action Handlers (Ejecutores de comandos)
├── Mapping Utilities (Herramientas de mapeo declarativo)
├── Transformation Helpers (Conversión de tipos, fechas, monedas)
├── Logging Engine (Trazas contextuales y sanitizadas)
├── Error Framework (Tipificación de errores y retryability)
├── Testing Harness (Mocks y validadores de contratos)
└── CLI / Utilities (Scaffolding y empaquetado)
```

---

## 6. Connector SDK (Ciclo de Vida)

```text
createConnector()
       ↓
metadata()      ──> Identificación, categoría y capacidades
       ↓
authenticate()  ──> Validación y captura de credenciales
       ↓
capabilities()  ──> Declaración de operaciones soportadas
       ↓
operations()    ──> Implementación de métodos (read, create, update...)
```

---

## 7. Metadata y Auto-descubrimiento

El conector declara su esquema descriptivo:

```text
Name:         Shopify
Category:     Ecommerce
Version:      1.0.0
Capabilities: Products, Orders, Customers, Stock
AuthType:     OAuth2
```

Permite al Core y al Dashboard renderizar dinámicamente formularios de configuración y paneles de control.

---

## 8. Entidades y Modelos Canónicos

El SDK expone definiciones tipadas para las entidades universales del negocio:
- `Product`
- `Customer`
- `Order`
- `Invoice`
- `Stock`
- `Supplier`

---

## 9. Abstracción de Autenticación

El SDK proporciona controladores (*handlers*) preconstruidos:
- **API Key:** Gestión de cabeceras y parámetros.
- **OAuth 2.0:** Flujos de autorización, almacenamiento seguro y refresco automático de tokens.
- **Basic Auth / Bearer Token:** Autenticación HTTP estándar.
- **Local Agent Bridge:** Canales de autenticación segura en local.

---

## 10. Emisión de Eventos (Event Emitter)

Permite que el conector notifique al Core cuando ocurran cambios relevantes:
- `ORDER_CREATED`
- `PRODUCT_UPDATED`
- `CUSTOMER_CREATED`
- `STOCK_CHANGED`

---

## 11. Ejecución de Acciones (Action Handlers)

Define el punto de entrada para ejecutar operaciones solicitadas por el Core:
- `CREATE_ORDER`
- `UPDATE_PRODUCT`
- `CREATE_CUSTOMER`
- `UPDATE_STOCK`

---

## 12. Utilidades de Mapeo Declarativo

Facilita la conversión entre el esquema del sistema externo y el modelo canónico:

```text
Shopify (product_id) ──> SDK Mapping Helper ──> ERP Bridge (id)
```

---

## 13. Funciones de Transformación Comunes

Utilidades integradas en el SDK para tareas habituales:
- `String ──> Number / Decimal`
- `Date ──> ISO 8601 String`
- `Currency Formatting (EUR, USD)`
- `Normalización de teléfonos y direcciones postales`

---

## 14. Modelo Unificado de Errores (`ConnectorError`)

```typescript
class ConnectorError extends Error {
  code: string;           // Ej: "RATE_LIMIT_EXCEEDED", "AUTH_INVALID"
  message: string;        // Mensaje legible
  operation: string;      // Ej: "getProducts"
  retryable: boolean;     // True si el Core debe reintentar con backoff
  details?: Record<string, any>;
}
```

---

## 15. Logging y Sanitización

Acceso a logger unificado con protección automática contra fuga de datos sensibles:

```text
logger.info("Sincronizando lote de productos", { count: 50 });
logger.error("Fallo de conexión", error);
```

*(El SDK filtra automáticamente tokens, contraseñas y datos bancarios de los registros).*

---

## 25. Seguridad y Aislamiento por Permisos

El SDK impone un modelo de permisos restringido:
- Un conector solo accede a los endpoints y credenciales de su propio sistema.
- **Ningún conector puede inspeccionar credenciales, datos o memoria de otros conectores.**

---

## 26. Alcance del MVP del SDK

### ✅ Incluido en el MVP:
- Connector Interface & Types.
- Modelos Canónicos esenciales (Product, Stock, Order, Customer).
- Handlers básicos de autenticación (API Key, OAuth, Local Agent).
- Clases de error estándar (`ConnectorError`) y Logging.
- Base de tests unitarios de contrato.

### ⏳ Pospuesto para Versiones Posteriores:
- CLI avanzada interactiva.
- Portal de desarrolladores web y marketplace auto-publishing.
- Monetización integrada y analytics de uso para desarrolladores.

## 28. Criterio de Éxito
