## 1. Propósito y Contexto de Mercado

**PrestaShop** concentra entre el **30% y el 40% del comercio electrónico consolidado en España**, dominando sectores tradicionales como ferretería, recambios de automoción, suministros industriales, textil y calzado.

### Por Qué es Crítico para los Usuarios de Factusol:
1. **Catálogos Grandes (10.000 a 80.000 referencias):** PrestaShop maneja bases de datos relacionales sin degradación de rendimiento.
2. **Fiscalidad Española:** Soporte nativo de **Recargo de Equivalencia (R.E.)** por grupo de clientes.
3. **Gestión de Combinaciones:** Matrices de tallas y colores sin el límite de 100 variantes que impone Shopify.
4. **Venta B2B Nativa:** Grupos de clientes con tarifas personalizadas y opción de ocultar precios al público general.

## 2. Arquitectura de Conexión: Web Service Oficial

* **Protocolo:** REST Web Service expuesto en `/api/` en el dominio de la tienda.
* **Autenticación:** HTTP Basic Auth mediante API Key generada en el Back Office (*Parámetros Avanzados > Web Service*):
  ```http
  Authorization: Basic <base64(API_KEY + ':')>
  ```

### 2.1 Estrategia Dual de Formato (JSON / XML)
* **Lectura (GET):** Se añade `?output_format=JSON` en los endpoints (`/api/products`, `/api/orders`, `/api/customers`). Permite una deserialización rápida en Node.js con mínimo overhead.
* **Escritura (POST / PUT):** PrestaShop 1.7 y 8 procesan las modificaciones mediante su parser interno `SimpleXMLElement`. Si se envía JSON, devuelve error 400/500.
  * **Solución ERP Bridge:** El conector serializa los datos canónicos a XML estricto mediante `fast-xml-parser` (`XMLBuilder`).

## 3. Desacoplamiento de Inventario: La Tabla `ps_stock_available`

En PrestaShop, el stock **no pertenece al objeto `ps_product`**, sino a la tabla relacional `ps_stock_available`:
* `id_stock_available` (Primary Key).
* `id_product` (ID del producto).
* `id_product_attribute` (ID de la combinación. Si es `0`, es el stock del producto simple o el total agregado del producto padre).
* `quantity` (Existencias físicas).

### Protocolo de Recálculo de Variaciones:
1. Al actualizar el stock de una variación (`PUT /api/stock_availables/{id}` con `id_product_attribute = X`), PrestaShop ejecuta internamente `StockAvailable::setQuantity()`.
2. PrestaShop actualiza automáticamente el registro maestro `id_product_attribute = 0` con la suma de todas las combinaciones:
   $$\text{quantity}_{\text{padre}} = \sum_{i=1}^n \text{quantity}_{\text{variación}_i}$$
3. **Caché de Mappings en SQLite:** ERP Bridge guarda en local la tupla:
   `{ sku: "REF-M-AZUL", id_product: 120, id_product_attribute: 450, id_stock_available: 890 }`.
   Esto permite emitir el `PUT` directo sin tener que hacer un `GET` previo para averiguar el ID de stock.

## 4. Alto Rendimiento: Micro-Módulo Acelerador Opcional

Dado que el Web Service nativo de PrestaShop procesa una petición por producto (carente de endpoint `/batch`), para catálogos superiores a 3.000 referencias ERP Bridge ofrece un micro-módulo gratuito open source (`erpbridge_sync`):
* Un único archivo PHP de <15 KB.
* Endpoint: `POST /module/erpbridge_sync/batch_stock`.
* Actualiza hasta **1.000 existencias directamente en MySQL mediante `ON DUPLICATE KEY UPDATE` en menos de 150 milisegundos**.
* Si el módulo no está instalado, ERP Bridge opera mediante la API oficial con concurrencia controlada (`p-limit(6)`).

## 5. Bidireccionalidad de Pedidos

1. **Lectura de Pedidos:** Polling cada 5-15 minutos a `/api/orders?filter[current_state]=[2,3]&display=full` (estados *Pago Aceptado* o *Preparación en Curso*).
2. **Inserción en Factusol:** Registro en `F_PCL` con referencia `REFPCL = 'PS-{order_id}'`.
3. **Cierre de Ciclo y Tracking:** Al expedirse el pedido en Factusol, ERP Bridge actualiza el estado del pedido en PrestaShop a *Enviado* (`id_order_state = 4`) e inyecta el número de seguimiento en `ps_order_carrier`.
