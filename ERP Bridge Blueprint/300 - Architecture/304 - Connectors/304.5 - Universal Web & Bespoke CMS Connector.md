# 304.5 - Universal Web & Bespoke CMS Connector (HTTPS Bridge)
> **Estado:** Especificación Técnica Aprobada  
> **Tipo:** Conector de Salida Universal (E-commerce / CMS a Medida / Portales Web)  
> **Prioridad:** Fase 1.5 (Mercado de Tiendas Propias, Desarrollos a Medida y Hosting Plesk / cPanel)

---

## 1. Propósito y Contexto de Mercado

El mercado de digitalización de la PYME tradicional española presenta una realidad recurrente: **miles de empresas no utilizan plataformas de comercio electrónico paquetizadas estándar como WooCommerce o PrestaShop**, sino que disponen de:
1. **Desarrollos web a medida o desacoplados:** Tiendas SPA en Angular, React, Vue o Svelte alojadas en hostings estándar (como Suministros Rubio).
2. **CMS y tiendas en PHP/Laravel/Symfony/WordPress sin WooCommerce:** Webs corporativas con catálogo interactivo, tiendas B2B ligeras o sistemas de pedidos personalizados.
3. **Entornos de Hosting Compartido o Gestionado (Plesk / cPanel):** Proveedores españoles (Raiola, Dinahosting, Arsys, Ionos, OVH) con soporte nativo para Apache/Nginx, PHP y bases de datos locales MariaDB/MySQL.

### El Problema Histórico de la Industria (La Trampa del Puerto 3306)
Históricamente, conectores de ERP antiguos (como **WebLinker** de SimplyGest o módulos OLEDB remotos) intentaban conectar el PC local de la empresa directamente contra el puerto **3306 (MySQL/MariaDB)** del hosting remoto a través de Internet. 

Esta arquitectura demostró ser un **fracaso operativo masivo**:
* **Bloqueo Perimetral:** El 98% de los hostings españoles tienen bloqueado el puerto 3306 en su cortafuegos por seguridad.
* **IPs Dinámicas:** Las PYMEs operan con fibra óptica bajo IP pública dinámica o CG-NAT (Movistar, Vodafone, Digi), haciendo imposible mantener listas blancas de IP fiables.
* **Ruptura de Certificados SSL:** Plesk y cPanel gestionan Let's Encrypt automáticamente para el servidor web (puerto 443), pero no para MariaDB en el puerto 3306. Forzar certificados en MariaDB provoca que cada 60-90 días el servicio crashee por discrepancias de permisos (`Permission Denied` en `root:root` 0600 vs `mysql:mysql`) o genere errores fatales de verificación de CA (`DEPTH_ZERO_SELF_SIGNED_CERT`) en Windows.
* **Riesgo de Fuerza Bruta:** Abrir el puerto 3306 a `0.0.0.0/0` expone el servidor a escaneos masivos que agotan `max_connections` y tumban la web de producción.
* **Mantenimiento Imposible:** El fabricante del ERP se convierte en el administrador de bases de datos (DBA) no remunerado de cada cliente, lidiando con migraciones de esquemas, bloqueos de tablas (`table locks`) y conflictos de codificación (`utf8mb4` vs `Windows-1252`).

**Solución ERP Bridge:** Se prohíbe terminantemente la apertura del puerto 3306 y se estandariza el **Micro-puente HTTPS en Puerto 443**.

## 3. Principios Fundamentales del Diseño

1. **Cero Puertos en Origen y Destino:**
   * En el router de la PYME no se abre ningún puerto (la conexión es 100% saliente).
   * En el hosting del cliente, el puerto 3306 permanece cerrado a Internet (`bind-address = 127.0.0.1`). Solo el puerto 443 estándar está abierto.
2. **SSL Nativo y Permanente:**
   * Al viajar por HTTPS (443), el conector se beneficia del certificado Let's Encrypt gestionado automáticamente por Plesk/cPanel para el dominio web (`https://tienda.cliente.com`).
   * No existe configuración manual de certificados SSL para bases de datos ni riesgo de caída cada 90 días.
3. **Cero Mantenimiento de Esquemas (Auto-Migración Idempotente):**
   * El micro-script PHP verifica la versión del esquema en cada arranque y crea o modifica las columnas necesarias (`ALTER TABLE IF NOT EXISTS`) de forma totalmente transparente y atómica.
   * El Agente en Windows nunca envía sentencias SQL directas (`CREATE`, `ALTER`); únicamente intercambia payloads estructurados en JSON canónico validado contra esquemas Zod.
4. **Desacoplamiento Absoluto de la Base de Datos:**
   * Si la tienda web del cliente está programada en Angular, lee los productos mediante una llamada HTTP simple (`GET /api.php?action=catalog`).
   * Si la tienda está programada en PHP o WordPress a medida, lee directamente las tablas locales `eb_products` sin intermediarios y con latencia de 1 ms.
5. **Cero Consumo de Infraestructura Central:**
   * La sincronización fluye íntegramente entre el PC del cliente y su propio hosting Plesk. La nube SaaS de Bentian (`bridge.cristianjm.com`) no almacena catálogos, no procesa imágenes ni consume RAM de servidor.

## 4. Especificación del Protocolo de Comunicación HTTPS

Todas las peticiones entre el **Local Agent** y el **Micro-puente PHP** se ejecutan mediante peticiones HTTP/1.1 o HTTP/2 bajo TLS 1.3 con codificación UTF-8 estricta.

### 4.1 Autenticación y Seguridad
Cada petición incluye las siguientes cabeceras obligatorias:
```http
POST /erp-bridge-endpoint.php HTTP/1.1
Host: tienda.cliente.com
Content-Type: application/json; charset=utf-8
Authorization: Bearer <SECRET_BRIDGE_KEY>
X-Bentian-Timestamp: 1789154400
X-Bentian-Signature: <HMAC-SHA256(timestamp + payload, SHARED_SECRET)>
X-Bentian-Agent-Version: 1.0.0
Idempotency-Key: <UUIDv4>
```

* **Prevención de Ataques de Repetición (Replay Attacks):** El script rechaza peticiones con `X-Bentian-Timestamp` con más de 300 segundos de diferencia respecto al reloj del servidor.
* **Integridad de Payload:** Si la firma HMAC no coincide exactamente, devuelve `401 Unauthorized` de inmediato sin consultar la base de datos.
* **Idempotencia:** La cabecera `Idempotency-Key` evita procesar dos veces el mismo lote en caso de reintentos por inestabilidad de red.

### 4.5 Endpoint 4: Confirmación y Acuse de Recibo de Pedidos (`ack_orders`)
Una vez que el Agente ha insertado con éxito el pedido en la cabecera `F_PCL` y líneas `F_LPC` de Factusol dentro de una transacción atómica OLEDB, notifica a la web para cambiar el estado a `PROCESSED_IN_ERP` y registrar el código de pedido interno asignado por Factusol (`CODPCL`).

* **Método:** `POST /erp-bridge-endpoint.php?action=ack_orders`
* **Payload JSON:**
```json

      "factusolSeries": "A",
      "status": "SYNCED",
      "syncedAt": "2026-09-12T11:01:15Z"
```

## 5. El Script de Enlace: `erp-bridge-endpoint.php`

Este componente es un **micro-script PHP autocontenido de archivo único (<8 KB)** que se deposita directamente en la carpeta raíz o subdirectorio del hosting del cliente (ej. `/httpdocs/erp-bridge-endpoint.php`).

### Características Técnicas del Script:
1. **Cero Dependencias:** No requiere `composer`, ni frameworks externos, ni librerías pesadas. Funciona sobre cualquier versión moderna de PHP (PHP 7.4, 8.0, 8.1, 8.2 y 8.3+).
2. **Conexión Local PDO Blindada:** Se conecta a MariaDB a través de PDO mediante el socket Unix nativo local (`/var/run/mysqld/mysqld.sock` o `127.0.0.1`), garantizando tiempos de respuesta < 2 ms y protección estricta contra inyecciones SQL mediante *prepared statements*.
3. **Auto-Instalación y Migración Automática (Zero-Maintenance):** En su primera ejecución, el script comprueba la existencia de las tablas canónicas y las crea automáticamente con soporte nativo de caracteres `utf8mb4_unicode_ci`.
4. **Invalidación de Caché Integrada:** Tras procesar un lote de existencias o precios, el script invoca ganchos de purgado de caché según el entorno detectado:
   * `opcache_reset()` para caché de código PHP.
   * Purga de LiteSpeed Cache mediante cabecera HTTP `X-LiteSpeed-Purge: *` si está presente el módulo LiteSpeed en Plesk/cPanel.

### Estructura Canónica de Tablas Autocreadas en MariaDB:

```sql
-- 1. Tabla de Artículos del Catálogo
CREATE TABLE IF NOT EXISTS `eb_products` (
  `code` VARCHAR(50) NOT NULL PRIMARY KEY,
  `sku` VARCHAR(50) DEFAULT NULL,
  `name` VARCHAR(255) NOT NULL,
  `description` TEXT DEFAULT NULL,
  `section_code` VARCHAR(10) DEFAULT NULL,
  `section_name` VARCHAR(100) DEFAULT NULL,
  `family_code` VARCHAR(10) DEFAULT NULL,
  `family_name` VARCHAR(100) DEFAULT NULL,
  `price` DECIMAL(12, 4) NOT NULL DEFAULT 0.0000,
  `vat_rate` DECIMAL(5, 2) NOT NULL DEFAULT 21.00,
  `price_with_vat` DECIMAL(12, 4) NOT NULL DEFAULT 0.0000,
  `unit_of_measure` VARCHAR(20) DEFAULT 'UNIDADES',
  `weight` DECIMAL(10, 3) DEFAULT 0.000,
  `barcode` VARCHAR(50) DEFAULT NULL,
  `active` TINYINT(1) NOT NULL DEFAULT 1,
  `updated_at` TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX `idx_family` (`family_code`),
  INDEX `idx_active` (`active`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 2. Tabla de Stock en Tiempo Real
CREATE TABLE IF NOT EXISTS `eb_stock` (
  `code` VARCHAR(50) NOT NULL PRIMARY KEY,
  `stock` DECIMAL(12, 3) NOT NULL DEFAULT 0.000,
  `updated_at` TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (`code`) REFERENCES `eb_products`(`code`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 3. Tabla de Pedidos Web
CREATE TABLE IF NOT EXISTS `eb_orders` (
  `id` INT AUTO_INCREMENT NOT NULL PRIMARY KEY,
  `order_number` VARCHAR(50) NOT NULL UNIQUE,
  `status` ENUM('PENDING', 'SYNCED', 'CANCELLED') NOT NULL DEFAULT 'PENDING',
  `customer_data` JSON NOT NULL,
  `order_lines` JSON NOT NULL,
  `payment_method` VARCHAR(50) NOT NULL,
  `payment_status` VARCHAR(50) NOT NULL,
  `payment_reference` VARCHAR(100) DEFAULT NULL,
  `subtotal` DECIMAL(12, 2) NOT NULL,
  `tax_total` DECIMAL(12, 2) NOT NULL,
  `shipping_cost` DECIMAL(12, 2) NOT NULL DEFAULT 0.00,
  `total` DECIMAL(12, 2) NOT NULL,
  `factusol_order_number` INT DEFAULT NULL,
  `factusol_series` VARCHAR(5) DEFAULT NULL,
  `created_at` TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `synced_at` TIMESTAMP NULL DEFAULT NULL,
  INDEX `idx_status` (`status`),
  INDEX `idx_created` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

## 6. Consumo desde el Frontend de la Tienda Web

El frontend del cliente queda completamente libre y desacoplado para consultar o crear datos:

### Caso A: Frontend en Angular / React / Vue (Ejemplo Suministros Rubio)
En la carpeta `httpdocs` se incluye un endpoint de lectura pública `api.php` que responde a las llamadas de Angular:
```typescript
// En article.service.ts de Angular
getArticulos(): Observable<Article[]> {
  return this.http.get<Article[]>('https://tienda.suministrosrubio.com/api.php?action=articulos');
}
```
* **Ventaja:** La web vuela a velocidad CDN/Nginx local. No hay llamadas a través de túneles hacia la oficina ni dependencia del estado del PC con Factusol.

### Caso B: WordPress a Medida (Sin WooCommerce)
En el archivo `functions.php` o template de WordPress:
```php
global $wpdb;
$productos = $wpdb->get_results("SELECT * FROM eb_products WHERE active = 1");
```
* **Ventaja:** Integración nativa a nivel de servidor sin plugins pesados.

## 7. Comparativa de Arquitectura: Por Qué Gana este Enfoque

| Vector Técnico | Conexión Directa MariaDB (3306) | WebLinker / FTP Antiguo | **Bentian Universal HTTPS Bridge (443)** |
| :--- | :--- | :--- | :--- |
| **Apertura de Puertos** | Requiere abrir 3306 en el hosting. | Requiere abrir puertos FTP/Pasivos. | **CERO puertos adicionales.** Puerto 443 estándar. |
| **Certificados SSL** | Pesadilla manual cada 90 días con caídas de servicio. | Sin cifrado o FTPS complejo de enlazar. | **100% automático.** Nginx y Let's Encrypt nativos. |
| **Seguridad de Red** | Expuesto a ataques de fuerza bruta al motor SQL. | Credenciales de FTP en texto plano en el ERP. | **Firma HMAC-SHA256 y Bearer Token en TLS 1.3.** |
| **Mantenimiento BBDD** | El desarrollador actúa como DBA manual de cada cliente. | Cero estructura (archivos CSV desincronizados). | **Tablas autogestionadas con auto-migración.** |
| **Coste Servidor Central**| 0 € pero alto coste de soporte por incidencias de red. | Coste de almacenamiento y servidores FTP. | **0 € absolutos.** Tráfico directo entre agente y hosting. |
| **Independencia Front** | Nula (exige backend específico). | Nula. | **Total:** Sirve para Angular, WordPress, React o PHP. |

## 8. Conclusión y Pautas de Implementación

El conector `304.5 - Universal Web & Bespoke CMS Connector (HTTPS Bridge)` proporciona la solución definitiva y elegante para cualquier proyecto e-commerce que no encaje en un marketplace o CMS preempaquetado:
1. Resuelve de inmediato casos reales en producción como **Suministros Rubio en Plesk**.
2. Convierte a Bentian en una herramienta universal capaz de sincronizar Factusol con **cualquier sitio web alojado en cualquier hosting del mundo** con soporte PHP.
3. Cumple escrupulosamente los principios de **Zero-Trust, Local-First, Cero Puertos y Desacoplamiento Canónico** del Blueprint.
