# 306 - API

> *Definición de endpoints, protocolos, contratos y APIs.*

---

## 1. Propósito

La **API de ERP Bridge** proporciona una interfaz programática para que aplicaciones, servicios y sistemas externos puedan interactuar con ERP Bridge de forma segura, estructurada y desacoplada.

Permite consumir las capacidades de integración desde:
- Tiendas Ecommerce (WooCommerce, Shopify, etc.).
- Sistemas CRM (HubSpot, Salesforce, etc.).
- Aplicaciones Web y Móviles a medida.
- ERPs y software de gestión.
- Servicios Cloud y plataformas de automatización.
- **Agentes de Inteligencia Artificial**.

---

## 2. Diferencia entre API y SDK

```text
              ERP BRIDGE
                  │
          ┌───────┴────────┐
          │                │
         API              SDK
          │                │
        USAR           EXTENDER
          │                │
    (Consumir)      (Crear conectores)
```

- **API:** Permite **utilizar** ERP Bridge desde sistemas externos (`Aplicación ──> API ──> ERP Bridge`).
- **SDK:** Permite **construir y extender** nuevos conectores (`Desarrollador ──> SDK ──> Nuevo Conector`).

---

## 3. Principio API-First

> **ERP Bridge se diseña teniendo la API como interfaz nuclear.**
> 
> La interfaz gráfica (Dashboard) es un consumidor más de la API, no la única forma de operar la plataforma.

```text
                  ERP Bridge
                      │
          ┌───────────┼───────────┐
          ↓           ↓           ↓
       Dashboard     API         SDK
```

---

## 4. Recursos Principales de la API

- `/connections`: Gestión de cuentas y conexiones activas.
- `/connectors`: Catálogo e inspección de conectores instalados.
- `/entities`: Operaciones canónicas sobre datos (Products, Orders, Customers...).
- `/flows`: Definición y control de flujos de integración.
- `/events`: Bus de eventos y suscripciones.
- `/executions`: Registro y trazabilidad de ejecuciones.
- `/users` & `/organizations`: Gestión de accesos y tenencia multi-empresa.
- `/agents`: Estado y control de Agentes locales vinculados.

---

## 5. Connections (`/connections`)

Gestión del ciclo de vida de las conexiones con sistemas:
- `POST /connections`: Registrar una nueva conexión.
- `GET /connections`: Listar conexiones activas.
- `GET /connections/:id`: Consultar estado y parámetros de una conexión.
- `PUT /connections/:id`: Actualizar credenciales o ajustes.
- `DELETE /connections/:id`: Desvincular y eliminar conexión.
- `POST /connections/:id/test`: Ejecutar test de salud y conectividad.

---

## 6. Connectors (`/connectors`)

Inspección de conectores instalados y disponibles:
- `GET /connectors`: Lista de conectores (Factusol, WooCommerce, Sage...).
- `GET /connectors/:id`: Información de versión, autor y metadatos.

---

## 7. Capabilities (`/capabilities`)

Consulta dinámica de capacidades soportadas por conector/conexión:

```http
GET /connectors/factusol/capabilities
```

```json
{
  "entities": ["products", "customers", "orders", "stock"],
  "operations": ["read", "create", "update"],
  "webhooks": false,
  "localAgentRequired": true
}
```

---

## 8. Entities (`/entities`)

Acceso normalizado a entidades de negocio a través de una conexión:
- `GET /connections/:id/products`: Obtener catálogo de productos normalizado.
- `POST /connections/:id/orders`: Crear pedido canónico en el sistema destino.
- `GET /connections/:id/stock`: Consultar niveles de inventario.

---

## 9. Flows (`/flows`)

Creación y administración de automatizaciones y sincronizaciones:

```http
POST /flows
```

```json
{
  "name": "Sync WooCommerce Orders to Factusol",
  "source": "conn_woo_123",
  "target": "conn_factusol_456",
  "trigger": "ORDER_CREATED",
  "mapping": "default_order_mapping",
  "active": true
}
```

---

## 10. Events (`/events`)

Suscripción e inspección de eventos del sistema (`ORDER_CREATED`, `PRODUCT_UPDATED`, `STOCK_CHANGED`).

---

## 11. Webhooks Salientes (Outbound Webhooks)

Notificaciones push enviadas por ERP Bridge hacia sistemas externos ante eventos clave:

```text
ERP Bridge ──(ORDER_CREATED)──> https://cliente.com/api/webhooks
```

---

## 12. Webhooks Entrantes (Inbound Webhooks)

Recepción de notificaciones push desde plataformas cloud para disparar integraciones en tiempo real:

```text
Shopify (Webhook) ──> ERP Bridge (Ingestion) ──> Flow Engine ──> Factusol
```

---

## 13. Executions (`/executions`)

Histórico detallado y auditoría de ejecuciones:

```json
{
  "id": "exec_98712",
  "flowId": "flow_orders_sync",
  "startedAt": "2026-08-18T10:00:00Z",
  "finishedAt": "2026-08-18T10:00:02Z",
  "status": "SUCCESS",
  "itemsProcessed": 1,
  "error": null
}
```

---

## 14. API Keys y Autenticación

Autenticación mediante cabeceras seguras (`X-API-Key` / `Bearer token`):
- Claves revocables y rotables de inmediato.
- Concesión basada en principio de mínimo privilegio.
- Sanitización estricta para evitar exposición en logs.

---

## 15. OAuth 2.0 *(Evolución Futura)*

Flujo de autorización para que aplicaciones de terceros puedan conectarse a ERP Bridge en nombre de una organización (sin necesidad en el MVP).

---

## 16. Permisos y Scopes Granulares

```text
API Key A
├── read:products
├── read:stock
└── write:orders
❌ write:users
❌ admin:billing
```

---

## 17. Multi-Tenancy y Organizaciones

Toda petición se contextualiza dentro del espacio lógico de la organización autorizada:

```text
API Request ──> Authentication ──> Tenant Context ──> Permissions ──> Resource Execution
```

---

## 18. Idempotencia (`Idempotency-Key`)

Cabecera para prevenir duplicación accidental de transacciones financieras o pedidos:

```http
POST /connections/:id/orders
Idempotency-Key: ord_7712_abc_2026
```

> Si la petición se reenvía por error de red, ERP Bridge devuelve la respuesta previa sin duplicar el registro en el ERP.

---

## 19. Rate Limiting y Protección

Protección contra saturación y ataques de denegación de servicio (ej. 100 req/min por tenant en planes base con cabeceras `RateLimit-*`).

---

## 20. Versionado Semántico de la API

Rutas con prefijo de versión estricto:

```text
/api/v1/connections
/api/v2/connections (en caso de breaking changes futuros)
```

---

## 21. Formato Unificado de Errores (RFC 7807)

```json
{
  "code": "ENTITY_NOT_FOUND",
  "message": "El producto con SKU 'ABC-123' no existe en Factusol",
  "requestId": "req_8f71aa9b",
  "timestamp": "2026-08-18T10:32:15Z",
  "details": { "sku": "ABC-123" }
}
```

---

## 22. Trazabilidad con Request ID

Cada llamada HTTP recibe un `requestId` único propagado en cabeceras de respuesta (`X-Request-Id: req_8f71aa9b`), permitiendo correlacionar incidencias de soporte directamente en los logs de auditoría.

---

## 23. Desacoplamiento API ↔ Local Agent

La API no conecta directamente con el socket del ERP local, sino que delega la instrucción al Core:

```text
Cliente Externo ──> API ──> Core Engine ──> Agent (Local Bridge) ──> Factusol / Access
```

---

## 24. Interacción con Agentes de Inteligencia Artificial (IA)

La API proporciona la capa de abstracción perfecta para agentes autónomos:

```text
Usuario: "¿Cuánto stock tenemos de Producto X?"
   ↓
Agente IA
   ↓
ERP Bridge API (GET /connections/factusol/stock?sku=X)
   ↓
Factusol Connector ──> Factusol Access
   ↓
Respuesta estructurada ──> Agente IA ──> Usuario
```

> **Ventaja:** La IA solo interactúa con el contrato de ERP Bridge; nunca necesita aprender la base de datos o API interna de Factusol, Sage o SAP.

---

## 25. La API como Infraestructura de Automatización

Sistemas CRM o plataformas externas pueden utilizar ERP Bridge como su propia pasarela de integración:

```text
HubSpot CRM ──> ERP Bridge API ──> Factusol (Crea Factura) ──> Notifica a WooCommerce
```

---

## 26. Separación: API Pública vs API Interna

- **Internal API:** Utilizada por el Dashboard, Local Agent y servicios internos del Core.
- **Public API:** Expuesta a clientes, desarrolladores, partners y agentes externos con rate limits y políticas de seguridad estrictas.

---

## 27. Alcance del MVP de la API

### ✅ Incluido en el MVP:
- Autenticación por API Key.
- Endpoints CRUD de Connections y Connectors.
- Endpoints de entidades básicas (Products, Orders, Stock).
- Recepción de Webhooks entrantes de ecommerce.
- Endpoints de estado de ejecuciones y Health check.

### ⏳ Pospuesto para Versiones Posteriores:
- OAuth 2.0 para aplicaciones de terceros.
- Interfaz GraphQL / gRPC.
- Streaming avanzado (WebSockets para clientes externos).
- Portal público interactivo de desarrolladores.

---

## 28. Criterio de Éxito

> **Una aplicación externa debe poder crear un pedido o consultar un stock en Factusol a través de la API sin saber en ningún momento que debajo existe una base de datos Microsoft Access local.**

---

## 29. Regla Fundamental

> **La API debe abstraer la complejidad de los sistemas conectados y proporcionar una interfaz consistente y moderna para operar ERP Bridge.**
